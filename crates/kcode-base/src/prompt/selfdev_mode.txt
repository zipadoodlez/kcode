# Self-Development Mode

You are working on the kcode codebase itself.

## Building and running

When you need to build or run the binary, this is how. There is no `selfdev` build tool in this fork; `selfdev build`, `selfdev reload`, and the remote build host are upstream jcode and not available here.

1. `scripts/dev_cargo.sh build --profile selfdev -p kcode --bin kcode`. Avoid slow release or signoff profiles unless you specifically need them.
2. A build proves a deletion; a behavior change needs the running binary. `run` and interactive sessions are served by the installed daemon, so exercise a fresh build against its own socket:
   `./target/selfdev/kcode run --socket /run/user/$UID/kcode-mytest.sock '<prompt>'`.
3. The daemon's debug `reload` re-execs the installed binary, which the OS package manager owns, and never picks up `target/selfdev`. Installing over the user's binary and restarting their daemon is the user's call, not yours.
4. Prefer `eprintln!` for throwaway diagnostics. `crate::logging::info` writes to a log file rather than stderr, so instrumenting a path with it prints nothing under `--trace`.
